# 의류 ML 학습·테스트 과정 및 최종 결론

기준일: 2026-11-24. 범위: 로컬 실험 기록과 현재 모델 매니페스트·API 안내. 경로는 별도 표기가 없으면 프로젝트 루트 기준이다.

> **최신 결정:** 기본 품목 모델은 **누적 Second-Hand +264 MLP seed 0**이며 실제 API·등록 CLI의 기본 경로 전환이 완료되었다. 과거 연구 보고서의 “API 변경 없음/승격 제안”은 그 보고서 작성 당시의 사실이지 현재 상태가 아니다. 비동기 분석은 아직 제안이며, 현재 분석 API는 배경 제거 완료를 기다린다.

## 1. 한눈에 보는 결론과 증거 수준

- **실험 사실:** 고정 FashionCLIP의 512차원 L2 특징 위에서 Linear와 MLP를 비교했다. 전체 백본을 미세조정한 실험이 아니다. 최신 head 학습 입력은 5,363장(기존 3,099 + Second-Hand 2,000 + 추가 264)이다.
- **선정 결정:** MLP 512→64→4 ReLU, seed 0, weight decay 0, 100 epochs. 새로운 동일 출처 holdout 200장에서 정확도 89.50%, macro-F1 89.55%. 이 수치를 서비스 정확도라고 부르지 않는다.
- **실측 속도:** 최신 raw 품목 경로 CPU warm n=40에서 MLP p50/p95 78.02/114.88ms, 누적 Linear 79.65/110.84ms. head 차이는 매우 작고, 전체 분석 병목은 배경 제거다.
- **별도 전체 경로 실측:** 원본 크기 Sample4 n=4, 배경 제거·속성·PNG/JSON 포함 로컬 벤치마크 31.596~40.720초. 실제 HTTP 처리시간이나 현재 API 전체 지연으로 대체하지 않는다.
- **권리 판단:** 데이터셋의 라이선스 표시는 개별 사진·인물·상표·백본 사전학습 권리를 보장하지 않는다. AIG 이미지·특징·연구 head는 research_only로 격리하고 서비스 학습에 혼합하지 않았다.
- **확인 필요:** 팀 실사진의 충분한 정답셋, 운영 HTTP 동시성·메모리·tail latency, confidence calibration, 소매·색·질감의 실사용 성능은 아직 확정할 수 없다.

이 문서의 수치는 저장된 보고서/JSON을 읽은 결과다. 이번 문서 작업에서 학습·추론·서버 기동을 재실행하지 않았다. 실제 uvicorn `/ready` 200 확인은 **실행 worker 보고 사항**으로 구분하며 본 문서 작성자의 독립 실측이 아니다.

## 4. 분할·학습·누수 검사

### 4.1 고정 학습 절차

- FashionCLIP revision `7e3ba62ce16b379a1ab479346b66f192e76f51b7`, frozen CPU 특징512D L2. Linear512→4(2,052 parameters), MLP512→64→4 ReLU(33,092 parameters).
- 최신 train 클래스 순서 `[상의, 하의, 아우터, 원피스]`의 수는 `[2346,1311,901,805]`, 합5,363.
- +264는 종전 체크포인트에 이어 학습한 것이 아니라 같은 누적 입력으로 **각 seed를 독립 초기화하여 재학습**했다.
- 기존 val741과 추가 val200의 지표로 설정 선택. 누적 Linear wd0.01/300 epochs, MLP wd0/100 epochs. test와 Sample4는 설정 선택에 넣지 않고 동결 후 평가했다.
- 추가 train264는 각 클래스66, 추가 val200/holdout200은 각 클래스50. 원래 eligible 잔여 val1,358/holdout1,264 중 아우터111/82 등 제약 아래 균형 표본을 만들었다. 검토용 풀 전체를 실제 학습 수로 계산하지 않는다.

### 4.2 검사 결과와 보증하지 못하는 것

누적 실험은 이전 700+2,700 item·검토 풀·기존 제외를 새 split에서 제외했다. split 간 item 중복0. 기존+Second-Hand 48,888개 감사 레코드 및 추가 잔여 1,328장 검역을 사용하여 exact/pHash≤6 교차 충돌0, Sample4와 새 집합 exact/pHash≤8 일치0을 기록했다. split 및 설정 동결은 `fixed_split.json`, `audit.json`, `freeze.json`에 남았다.

AIG는 train/val/test1,400장 사이 ID·중복 그룹·encoded/RGB hash·pHash≤4 충돌0. 기존과 근접 일치한 437행→64 전이 그룹→3,848행은 모든 split에서 제외했다(서로 겹치는 제외 집계를 합산하지 않음). 누적 head의 AIG 평가에는 AIG train/val 특징을 읽거나 학습시키지 않았다.

해시 통과는 다른 촬영/판매자/배경/크롭, 의미상 같은 상품, 실제 SKU 단위 분리, FashionCLIP 사전학습 중복을 완전히 배제하지 못한다. AIG item ID/원사진 출처도 미확인이다. Fashionpedia처럼 이미지 없는 자료는 이미지 교차검사 범위에 들어가지 않는다.

DeepFashion의 보수적 그래프는 172 component, 최대281,788장(97.43%)을 만들었다. 이것이 모두 같은 상품이라는 뜻은 아니지만 이 제약으로 의도한 안전한 분할을 만들 수 없었다. giant component를 임의로 잘라 train/test에 흩뿌리지 않았다. 잔여 원피스160장으로 목표 pilot 규모도 충족하지 못했다. 폴더명 약라벨을 인증 GT/SKU로 간주하지 않았기에 학습 점수를 만들지 않았다.

## 5. 모델 성능: 동일 코호트·대표 seed 비교

아래 모든 셀은 **정확도% / macro-F1×100**. 모두 동일 이름·ID의 코호트에 대한 저장 비교값이다. `—`는 해당 동결 모델의 평가 기록 없음이며 다른 200장 테스트로 대신 채우지 않았다.

### 5.1 seed의 뜻과 평균을 읽는 방법

seed는 난수 초기화 등의 재현 번호다. seed0/1/2는 같은 학습·검증·시험 split 위의 반복이며 서로 다른 테스트 표본도, 세 모델 투표 앙상블도 아니다. 대표 seed0은 사전 대표값이지 test 최고 seed를 골라 쓴 것이 아니다. SD는 초기화 민감도의 표본 표준편차이며 데이터 표본 신뢰구간이 아니다.

| 동일 추가 holdout200 | seed0 Acc/F1 | seed1 Acc/F1 | seed2 Acc/F1 | 3 seed 평균 Acc/F1 |
|---|---:|---:|---:|---:|
| 확대 Linear | 87.50/87.39 | 87.50/87.39 | 87.50/87.39 | 87.50/87.39 |
| 누적 Linear | 88.50/88.44 | 88.50/88.44 | 88.50/88.44 | 88.50/88.44 |
| 확대 MLP | 89.00/89.05 | 88.50/88.55 | 88.00/88.07 | 88.50/88.56 |
| 누적 MLP | 89.50/89.55 | 89.50/89.55 | 89.50/89.55 | 89.50/89.55 |

누적 MLP의 다른 코호트 **seed 평균**은 Clothing570 95.67/93.02, 확대400 90.33/90.18, 이전Second-Hand200 89.50/89.49이다. 위 대표 seed0 표의95.79/93.43,90.00/89.84와 혼동하지 않는다. 추가 holdout의 평균 recall은 상의84.67/하의98.00/아우터86.67/원피스88.67%. 이전 test200에서는 대표 seed0 아우터 recall이 MLP86% vs 누적 Linear88%로 반대 trade-off도 있다.

AIG200에서 누적 MLP는 seed0/1/2 각각96.00/96.50/96.00%, 평균96.1667±0.2887%p, F1 0.96139480±0.00288509이다. 누적 Linear는93.00/93.50/93.00%, 평균93.1667±0.2887%p, F1 0.93158195±0.00283105. AIG-only train1,000으로 학습한 두 아키텍처 각3 seed는 모두198/200=99.00%, F1 0.98999950이었다. 이는 **서로 다른 학습자료**의 연구 결과이지 264장 추가 효과나 MLP 일반 우위의 증명이 아니다.

### 5.2 현재 선정 이유와 포기하는 것

누적 MLP는 대표 seed0 기준 위 네 코호트에서 누적 Linear보다 macro-F1이 높고 raw 품목 지연의 실질 차이도 작다. 4코호트 F1 단순평균은92.20 vs90.90, AIG 제외3개 평균도90.94 vs90.20이다. 단순평균은 각 코호트1/4이며 Second-Hand가 두 번 들어가 총1/2이므로 운영 입력 비중 추정치가 아니다.

누적 MLP가 모든 후보를 이긴 것은 아니다. 초기 혼합 MLP는 Clothing570에서 F1 +2.08p/정확도 +1.58%p 우세하지만 누적 MLP는 Second-Hand400과 AIG200에서 더 낫다. 확대MLP와 누적MLP의 비-AIG3코호트 대표 F1평균은91.11 vs90.94로 확대가 약0.18p 앞서며 3 seed평균은90.891 vs90.918로 사실상 비슷하다. 확대MLP의 AIG 결과는 없으므로 네 코호트 우열은 미확인이다. 현재 선택은 최신 동결·입력 계약·진단 범위를 갖춘 후보의 파일럿 선택이지 전 도메인 최고 모델 인증이 아니다.

## 7. 실제 API·CLI 적용 상태

현재 기준 문서는 `ml/README.md`, `ml/GARMENT_CATEGORY_MODEL.json`, `docs/ml-api/README.md`다. 과거 AIG RECOMMENDATION과 CPU REPORT의 “당시 Linear 마스크 크롭 기본” 설명을 이 절의 최신 결정으로 대체하여 읽는다.

- 기본 `GARMENT_CATEGORY_MODEL=mlp`. API 및 등록 CLI는 동일 누적MLP seed0을 사용한다. 명시적 `legacy-linear`는 비교용 raw Linear이며 자동 fallback이 아니다.
- 기본파일: `ml/weights/garment4_mlp_secondhand_balanced264_20261124_seed0.pt`.
- 크기 **135,005 bytes**, SHA-256 **`59232b1a34deb046984cce8b9d68dfd2a852ae53aa899ce62e5aae695eb7bd10`**. 원산출물 `out/garment4_secondhand_balanced264_20261124T0429053807666Z/cumulative_mlp_seed0.pt`의 동일 사본이다.
- 품목 입력은 **EXIF 보정·투명도 흰색 합성·RGB 원본 전체 프레임**→고정 FashionCLIP processor(내부 resize/center crop)→L2벡터→MLP. 마스크 표시 크롭의 벡터로 품목을 분류하지 않는다.
- 공개 `embedding`은 기존과 같은 긴변2048 제한 표시 크롭 기반512D L2 벡터다. 품목용 raw벡터는 반환하지 않는다. `model_versions.embedding` 계약을 유지하므로 품목 모델 변경만으로 기존 옷장 벡터를 재계산하지 않는다. 소매·대표색 probe도 기존 크롭 경로를 유지한다.
- `/v1/garments/analyze/attributes`는 기존 분석 응답을 보존하고 속성을 추가하는 선택 경로다. 현재 API는 여전히 배경 제거·크롭 등을 기다린 뒤 응답한다. raw의 약0.1초 실측을 곧바로 API 응답시간으로 광고하면 안 된다.
- 기본 MLP가 없거나 해시가 다르면 시작 실패. 품목 가중치는 역직렬화 전에 핀 해시 검사. 고정 FashionCLIP/BiRefNet의 검토된 로컬 캐시가 필요하고 런타임 다운로드로 메우지 않는다.

연동 문서의 읽기30초 예시는 제안값이다. 위 로컬 원본크기 벤치마크가30초를 넘으므로 운영 입력 제한·동시성·재시도 정책을 실제 API에서 측정해 재조정해야 한다.

## 8. GitHub 운영·자산 공급 주의

**현재는 GitHub 공개 준비만 했고 push하지 않았다. 작업 환경에 git이 없어 실제 커밋/원격 동기화를 검증하지 않았다(최신 작업 보고 기준).** GitHub 저장소 공개와 서비스 배포는 별도 승인 사항이다.

1. `data/`, `weights/`, `*.pt`, 원본/샘플 사진, `out/`, 모델·특징 cache, 가상환경 및 `.env`/실제 키를 커밋·업로드하지 않는다. ignore 목록만 믿지 말고 실제 staged 파일과 추적 이력을 확인한다.
2. 코드만 받은 환경은 기본 모델이 없으므로 바로 실행되지 않는다. 권리 검토된 로컬 사본/승인 팀 자산 경로에서 동일135,005-byte MLP와 고정 모델 캐시를 별도로 공급한다. manifest와 귀속·변경 고지를 함께 유지한다.
3. AIG·DeepFashion·Commons BY-SA 원본/파생 crop/특징/연구 head를 서비스 기본자산이나 공개 릴리스에 섞지 않는다. 데이터셋 라이선스나 내부 실험 승인을 사진 재배포 허가로 간주하지 않는다.
4. 신뢰되지 않은 `.pt`는 로드하지 않는다. `weights_only=True`나 SHA 일치만으로 원출처의 안전성·권리가 확보되지는 않는다.
5. 실제 키·사진·벡터가 로그·테스트 fixture·문서·커밋에 없는지 로컬에서 확인한다. 이번 문서 작업은 민감 설정 파일을 열거나 외부 서비스에 저장/발송하지 않았다.

## 9. 파일럿 계획 — 아직 실행/합의되지 않은 제안

### 우선순위 1: 진짜 운영 입력과 사람 정답

- 권리·동의가 확인된 팀 실사진을 품목·의복·촬영자 단위로 수집하고 얼굴/GPS 등 개인정보를 제거한다. 한 벌 정면·단색 배경을 우선하되 착장·다품목·조명 문제는 별도 도전셋으로 둔다.
- 학습/validation/최종 holdout을 의복·촬영자 단위로 고정한다. 평가 전 GT를 동결하고 상의/아우터 경계·색 팔레트·질감 복수선택 기준을 합의한다.
- 기본MLP와 명시적 legacy Linear를 같은 파일·동일 전처리에서 비교한다. 품목 accuracy/macro-F1/품목별 recall/확인필요 오답검출·헛경보, 색 strict/top-k, 질감 후보순위·판단어려움을 분리 보고한다.
- 임계값은 validation에서만 정하고 최종 holdout을 다시 튜닝에 쓰지 않는다. 모델 교체 판단에는 실패유형·촬영자별 편차도 포함한다.

### 우선순위 2: 속도·안정성

- 실제 uvicorn HTTP 입력 decode→raw품목→마스크→색/질감→직렬화의 시간을 따로 측정한다. cold/warm, 입력크기, 동시요청, RSS/peak, timeout·오류율을 함께 남긴다.
- **비동기 bounded queue로 품목 초안과 배경 제거/속성 완료를 분리하는 것은 제안**이다. 아직 구현되지 않았다. 별도 CPU worker·큐 상한·취소·재시도·대기 상태 표시를 설계해야 한다.
- 초기 제안 SLO는 warm품목 p95≤500ms 및 비동기 전체90초 이내 완료다. 운영 실측 달성치나 합의된 보장은 아니다.
- 512마스크/색픽셀cap은 마스크·색GT 회귀 평가를 먼저 통과시켜야 한다. 현재 속도 이득만으로 채택하지 않는다.

### 우선순위 3: 외부·권리 검증

Commons 미확보39개는 합법적 로컬 제공과 검수 뒤에만 평가한다. 자동 수집 재개나429 우회는 제안하지 않는다. DeepFashion은 인증된 이미지별 주석·안정적인 item ID 확보 또는 연구 목표를 약라벨 benchmark로 바꾸는 명시적 결정 없이는 학습 비교를 진행하지 않는다. AIG는 권리 체인 문제가 해소될 때까지 연구전용 격리를 유지한다.

## 10. 최종 한계와 미결 사항

- 대부분의 holdout/test는 이미 관찰된 재평가 자료이며 반복적인 후보 비교로 탐색 편향이 생길 수 있다. 신규 Second-Hand holdout도 같은 출처 균형 전면 사진이라 새로운 촬영환경을 대표하지 않는다.
- test200에서는 한 장이 accuracy0.5%p, 품목별50장에서는 recall2%p다. 작은 차이나 seed SD를 일반화 확신으로 확대하지 않는다.
- 공급자 라벨 오류·배경 제거224px 편향·CLIP 중앙크롭·사람/배경/다품목 오염이 남는다. 자동 마스크 품질의 독립 GT 평가는 없다.
- 추천 자산, 선택 소매·색 head, 충분한 팀 정답셋이 없어 기능 전체 품질을 보증할 수 없다. 색·질감은 사람 확인을 전제로 한다.
- 기본 모델 전환은 완료되었으나 비동기 처리, 운영 SLO, 외부 재배포 승인, 가중치 배포 채널, 확대MLP의 AIG 평가, DeepFashion 정식 head 비교는 미결이다.

**최종 판단:** 현재는 누적MLP seed0을 기본으로 실제 API/CLI에서 일관된 raw품목 계약을 사용하되, 공개 embedding은 보존하고 색·질감은 검토 후보로 제공한다. 다음 개선의 핵심은 head를 더 복잡하게 만드는 것보다 권리 확인된 운영 정답셋, 배경 제거 병목, 품목별 실패 검토다.
