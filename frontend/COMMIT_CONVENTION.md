# 커밋 규칙

[Conventional Commits](https://www.conventionalcommits.org/ko/v1.0.0/) 형식을 따릅니다.

## 형식

```
<type>(<scope>): <subject>

<body>

<footer>
```

- `scope`, `body`, `footer`는 선택 사항입니다.
- 헤더(첫 줄)는 `type`과 `subject`만 필수입니다.

## Type

| type | 설명 |
| --- | --- |
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 수정 |
| `style` | 코드 동작에 영향 없는 포맷팅 변경 (공백, 세미콜론 등) |
| `refactor` | 기능 변화 없는 코드 구조 개선 |
| `perf` | 성능 개선 |
| `test` | 테스트 코드 추가 및 수정 |
| `build` | 빌드 설정, 패키지 의존성 변경 |
| `ci` | CI 설정 변경 |
| `chore` | 그 외 잡무 (설정 파일, 폴더 구조 등) |
| `revert` | 이전 커밋 되돌리기 |

## Subject 규칙

- 50자 이내로 간결하게 작성합니다.
- 마침표를 붙이지 않습니다.
- 명령형 현재 시제로, "무엇을 했는지" 작성합니다. (예: `추가`, `수정`, `제거`)
- 영어로 작성할 경우 첫 글자는 소문자, 동사 원형으로 시작합니다.

## Body 규칙

- 헤더와 한 줄을 띄우고 작성합니다.
- "무엇을"보다 "왜", "어떻게"를 설명합니다.
- 한 줄은 72자 이내로 줄바꿈합니다.

## Footer 규칙

- 이슈 연결: `Closes #12`, `Fixes #34`, `Refs #56`
- 호환성을 깨는 변경은 `BREAKING CHANGE: <설명>`으로 명시합니다.

## 예시

```
feat(login): 소셜 로그인 버튼 추가
```

```
fix(header): 모바일에서 메뉴가 겹치는 문제 수정

뷰포트 폭이 640px 미만일 때 nav가 로고를 덮는 현상이 있었다.
flex-wrap을 적용해 줄바꿈되도록 변경했다.

Closes #23
```

```
refactor(api): 요청 공통 로직을 훅으로 분리
```

## 기타 원칙

- 하나의 커밋에는 하나의 논리적 변경만 담습니다.
- 빌드나 테스트가 깨진 상태로 커밋하지 않습니다.
- 작업 중간 저장용 커밋(`wip`, `temp`)은 PR 전에 정리합니다.
